# 第 29 轮：常驻 AI 主编（这个程序真正的操作者）

日期：2026-09-28
作品：morning-brief（晨报卡）0.1.0
本轮目标：把「一个会挑新闻的卡片」变成「一个随时能被使唤的编辑部」——加一层常驻智能体，
它能看懂界面、能动手操作这个程序里的一切，用户说一句话就能把事办完；同时按 UI 反馈做视觉升级。

## 一、做了什么

### 1. 常驻 AI 主编（四层结构）

按「感知 → 决策 → 工具 → 界面」四层落地，全部在 `main.splash` 内，用官方 `llm.chat`：

| 层 | 函数 | 作用 |
| --- | --- | --- |
| L1 感知 | `ag_context()` | 把界面现状讲给模型：当前在哪一页、主题/条数/关注点、这一期入选了哪些条目、正在读哪条 |
| L2 决策 | `ag_turn()` / `ag_reply()` | 多轮工具调用循环：读用户的话 → 输出 `{say, tool, args}` → 执行 → 把结果喂回去 → 最多六步 |
| L3 工具 | `ag_tools` / `ag_do()` | 12 个工具，覆盖界面上的全部操作（见下表） |
| L4 界面 | `ag_dock` | 常驻对话条：右下角胶囊按钮展开，气泡对话流 + 输入框 + 三个快捷短语 |

**12 个工具**：`set_topics`（换主题）、`set_limit`（改条数）、`set_intent`（写关注点）、
`make_plan`（生成计划）、`approve`（批准取数）、`deny`（取消）、`restart`（重新开始）、
`open_story`（打开第 i 条）、`close_story`（返回列表）、`step_story`（前后条）、
`redraw_cover`（换头版）、`draw_art`（画配图）。

关键设计：
- **感知是快照，不是猜测**：每次调用都把「现在界面上是什么」重算一遍塞进 system 提示，模型不需要记住状态。
- **工具只走一个入口**：`ag_do()` 是唯一派发点，界面上每个按钮在这一层都有对应，不存在「AI 能做的」和「人能做的」两套逻辑。
- **多轮对话记忆**：`ag_msgs` 保留最近 10 条，够模型理解「打开第一条」指的是刚才那期。

### 2. 联网硬闸门（守住「先授权、后联网」）

主编能调用 `approve`（真的联网），所以加了两道锁：
- **代码闸门 `ag_user_approved()`**：只有用户原话里出现「批准 / 开始取数 / 同意 / 开始吧 / 去取数 / 确认取数」才放行，否则工具直接返回「还没批准」。
- **提示词约束**：明确告诉模型「用户只说生成时不可以调用 approve，要停在待批准页请他确认」。

实测：用户说「只看 AI 和芯片，生成今天的晨报」→ 主编调 `set_topics` + `make_plan`，停在待批准页；
用户说「批准，开始取数」→ 主编才调 `approve`。**没有出现越权联网**。

### 3. 未完成自动续推

模型偶尔会「嘴上说要做，实际没调用工具」（说「这就给你出计划」但不调）。加了 `ag_unfinished()` 检测：
用户请求是任务型（含「生成 / 晨报 / 来一份 / 看今天」等）而界面还停在首页时，自动喂一条系统提示把它推回去真的做，最多推 2 次。

### 4. UI 升级（按反馈）

- **首屏深色刊头**：`#x0e1424` 圆角深底 + 白字大标题 + 洋红副标「MORNING BRIEF · AI EDITION · 常驻主编在线」
- **今日头版改 hero**：268→196px 深色全幅卡片，图片铺底 + 深色蒙版 + 白色大标题压在图上 + 右下角玻璃质感「换一张头版」按钮
- **列表条目加编号**：`01 · 来源 · 时间` 前缀，编辑部的取舍顺序一眼可见
- **计划页动作前置**：「批准并取数 / 暂不」提到计划标题下方，不再被长文本挤出可视区

### 5. 开场 CG 增加轨道环

在现有「Dawn / 破晓」时间轴上加了倾斜的椭圆轨道环（早期淡入、收尾淡出），呼应 PyMaster 那种深色沉浸式视觉。

## 二、本轮修掉的三个真 bug（都是历史遗留）

### 1. `pad2()` 数字拼串崩溃 —— 最隐蔽的一个

```splash
fn pad2(n){
    if n < 10 { return "0" + n }   // ← 灾难
    "" + n
}
```
数字拼串必须先转文本。之前 `pad2` 只被 `gen_time()` 调用，且时分永远是两位数，所以**这个分支从未被执行过**——
直到本轮列表编号 `01`、`02` 开始走个位数分支，整段 `on_render` 中断，列表只渲染出第一行。
修法：先 `let t = "" + n` 再拼。这个坑写进了交接文档。

### 2. `rank_of(r)` 在渲染循环里再遍历 `show_rows()` —— 打断外层迭代

第一版编号用 `rank_of(r)` 反查下标，而它内部又调 `show_rows()`。
在 `else for r in show_rows()` 循环体内再遍历同一个数据源，会导致外层迭代中断（同样表现为只渲染第一行）。
修法：改成带索引的 `for i r in rows`，编号用纯函数 `rank_text(i)` 由下标算，渲染循环里零额外遍历。

### 3. HN 缺 `url` 字段导致取数卡死

`hit.url` 在字段缺失时**直接抛错**（不是返回 nil），而 HN 的「Ask HN」类帖子天生没有 url。
后果：一旦命中这类帖子，整轮取数中断，界面永远停在「正在获取 2 个来源…」。
修法：全部改成「先取键再判空」（`let u = hit["url"]`），并给 `load_source()` 包 `try`、
给取数加 45 秒看门狗（卡住就按失败收口，界面不会永远转圈）。
