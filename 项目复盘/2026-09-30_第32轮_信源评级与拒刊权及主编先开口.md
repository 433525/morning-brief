## 一、做了什么

### 1. 信源评级：每条新闻先说清它是一手还是转载

新增 `tier_of_h()` / `tier_of()` / `tier_label()` / `tier_add()` / `tier_tally()`，按**域名**把每条新闻分四类：

| 等级 | 含义 | 判定 |
| --- | --- | --- |
| **一手** | 官方博客 / 代码仓库 / 论文 / 官方公告 | `tier_first` 里的域名（github.com、arxiv.org、openai.com、rust-lang.org… 共 42 个） |
| **二手** | 媒体报道 | `tier_second`（techcrunch、reuters、36kr、机器之心… 共 31 个） |
| **传闻** | 社交平台，未经证实 | `tier_rumor`（x.com、reddit、weibo… 共 11 个） |
| **转载** | 聚合站、内容平台 | `tier_repost`（news.ycombinator.com、techmeme、medium… 共 12 个） |

两个刻意的设计决定：

- **判定顺序是 传闻 → 转载 → 一手 → 二手**。如果先判一手，`news.ycombinator.com` 里的 `ycombinator` 会被当成 YC 官方，而它其实只是个聚合入口。顺序错了，整套评级就废了。
- **认不出的域名一律算「二手」**，不算「转载」。因为"我们认不出你"不该变成一种指控 —— 宁可高估。

评级**直接显示在卡片上**：`row_meta()` 的第一段就是等级，所以列表里每条新闻读起来是
`01 · 一手 · Hacker News · 8h ago`。这是零 UI 改动、但曝光度最高的一处。

评级还进了主编的提示词：候选名单从 `0. 标题` 变成 `0. [一手] 标题`，并在 system 里加了一条硬规矩 ——
**标注「传闻·未证实」的条目最多只允许入选 1 条，且入选理由里必须写明「尚未证实」。**

### 2. 拒刊权：主编有权不出报，读者有权否决主编

`refuse_check()` 在取数之后、终审之前插了一道闸。判据刻意保守：

```
一手 == 0  且  二手 <= 2
```

也就是**整个候选池几乎全是聚合站和社交平台**的时候才触发。因为认不出的域名算二手，
正常情况下这条闸几乎不会亮 —— 它要真的罕见，才有分量。

触发后进入新的 `phase == "refused"`，出**「今日休刊」**页（沿用报头那套夜色仪式感 + 晨金分隔线）：

- 写明理由：「候选池里一手来源 0 条，二手 2 条，其余 7 条传闻、9 条转载。今天这些消息我没有把握，不想拿一个二手转述来充今天的晨报。」
- 底下两行数据：本期信源构成、本期淘汰率
- 两个按钮：**「仍要出报」**（`refuse_go()`，读者否决主编）和「重新开始」
- 页面底部一句话写着：**「拒刊是主编的判断，不是对你的束缚 —— 决定权在你手里，你说了出，我就出。」**

这一条是整个功能里我最满意的地方：拒刊本身是"产品有性格"，但**加上读者的否决权，它才不傲慢**，
而且它跟这份产品原有的授权门哲学（联网要你批准、不补齐条数）是同一套价值观。

### 3. 工作量与信源构成公开

新增 `work_line()` / `tier_line()`，显示在结果页报头下方的浅色小条里：

```
214 条里见报 10 条，淘汰率 95%
本期信源：一手 12 · 二手 9 · 传闻 2 · 转载 7
```

`work_n` 在 `gather()` 里从 `all_rows.len()` 取（两个来源的原始条数），`work_cand` 是去重排序后的候选池。
**「淘汰率」这个数字比任何功能描述都能说明"这份报不是随手抓的"。**

### 4. 出报前的一问：主编先开口

原来的流程是「点生成 → 出计划 → 批准」。现在中间插了一步：

**点「生成晨报」→ 主编先问一句「今天更想看哪个角度？」→ 给你 A / B 两个选项 → 你选完才出计划。**

关键是**选项不是摆设**：选中的那句话会真的写进 `ask`（本期关注点），
而 `ask` 会进终审提示词、进计划页、进读者画像。所以这个"问"是有效果的，不是表演。

- 新增 `phase == "asking"` + `aq_shape`（`{q, a, b}`）+ `aq_pane`
- 可以**语音回答**：主编新增工具 `pick_angle {which: "a"|"b"|"skip"}`，`ag_context()` 里把问题和两个选项原样告诉它
- 有「你定，不用问」的出口，也可以直接跳过
- LLM 若没给答复，自动降级直接进计划，不阻塞
- 首页按钮改指向 `aq_start()`，但**工具 `make_plan` 保持原路**（主编自己调用时不该再问自己一遍）

### 5. 采访草稿箱（把"疯狂档"做成了半条腿）

原创意清单把「主编写信采访当事人」归在**第三档·疯狂**。动工前我查了一遍宿主能力，得到两个结论：

- ✅ 生成一封克制的追问邮件**可以做**
- ❌ 把信**发出去**做不到（见「二、1」）

所以做成：阅读页加「写封信追问」按钮 → 主编读完原文起草一封**只问一个具体问题、正文不超过三句**的邮件 →
落盘 `outbox.json` → 界面明写**「发信不在这份程序里 —— 需要你在外部确认后自己发」**。

工具层新增 `draft_interview`，并在 system 里补了一句：
**「你只写稿存本机，发信是他在外部的动作，你永远不替他发。」**

### 6. 分段朗读：能插话，能从断点接着念

宿主给的语音接口只有 `llm.speak`（说）和 `llm.speaking`（在不在说），**没有停止播放**。
所以"真打断"是不可能的。能做的是**分段队列**：

- `rv_build()` 把导语 + 前五条标题拆成句子入队
- `rv_next()` 一句一句念，`rv_watch()` 轮询 `llm.speaking` 判断这一句念完没有
- **插话**：`vc_poll_go()` 收到识别结果时，如果正在朗读，先 `rv_stop()` 停掉队列 —— 当前这句念完就把话筒交给你
- **断点保留**：`rv_stop()` 不清空 `rv_q` 和 `rv_i`，所以按钮会从「念这一期」变成「接着念」
- 界面显示「正在念 · 第 3 / 7 段」，按钮文字实时变成「■ 停下」

这里有个我自己发现并修掉的隐患：`llm.speak` 是异步的，第一轮查询 `llm.speaking` 时可能还没开始播；
而有的宿主根本不提供这个接口，`playing` 会永远是 `false`，导致每 0.9 秒跳一段、整期瞬间"念完"。
修法是加一个**两轮（约 1.8 秒）的最小等待下限** —— 最坏情况是每段都等满 1.8 秒，也不会跳着念完。

### 7. 工具层：15 → 19

新增四个：`read_brief`（分段念）、`stop_read`（停下）、`pick_angle`（答出报前那一问）、`draft_interview`（起草追问）。
`ag_context()` 也扩了：现在会把**信源构成、工作量、拒刊理由、主编问出去的那一问与两个选项、草稿箱数量、朗读断点**都告诉主编。

## 二、技术上的三个决定

### 1. 「主编的邮箱」为什么只做了一半 —— 这条最值得记

我原本打算把"主编发信采访"完整做进 `main.splash`。动工前先枚举了一遍宿主能力：

```
host.request 用到的全部接口（grep 全文件）
  llm.chat × 7    llm.status × 1    llm.speech × 1
  llm.speak × 1   llm.speaking × 1
  llm.listen_start × 1   llm.listen_poll × 1   llm.listen_stop × 2
```

**没有邮件、没有外部投递、没有任意 POST。**

这暴露了一个我一开始想错的地方：我在上一轮的建议里说"主编的邮箱连接器已就绪，所以这条现在可做"。
**那个连接器接的是我（WorkBuddy 侧的智能体），不是跑在 OctoSense 宿主里的这张卡片。**
卡片能用的只有宿主给的这几个接口。这是两套完全不同的能力边界，我把它们混为一谈了。

所以最终做法是：**把"写稿"和"投递"拆开**。

- 写稿放在卡片内（有 LLM，能做）
- 投递放在卡片外（需要外部能力，读者自己确认）

这个拆分反而让功能更符合产品价值观：**能力可以给，把信发出去的那只手不能自己伸。**
真机上如果你想补上投递腿，有两条路（都已写进交接文档）：
① 宿主若允许外发就补在卡片里（仍需保留"你先点头"这一环）；
② 做成代理模式 —— 外部工具读 `outbox.json` 再发。

### 2. 这个 DSL 没有 `ends_with`，域名匹配得绕一下

`tier_of_h()` 要判"这个 host 属于不属于某个域名"。语言里没有 `ends_with` / `contains`，
只有 `search()`（返回下标）。最直觉的写法是 `h.search("x.com") >= 0` —— **这是错的**：

```
netflix.com  →  包含 "x.com"  →  被判成「传闻」
```

修法是两步：先判相等，再判 `"." + d` 的后缀。

```
fn dom_hit(h, d){
    if h == d { return true }
    if h.len() <= d.len() { return false }
    h.search("." + d) >= 0
}
```

这样 `blog.cloudflare.com` 能命中 `cloudflare.com`（子域放行），而 `netflix.com` 不会命中 `x.com`。
**认不出的域名反而是安全的** —— 这条规则已经写进 `AGENTS.md` 的红线。

### 3. 整块替换时，锚点绝不能落在容器第一行

这一轮踩得最实的一脚，值得单独记。

我用脚本给阅读页插采访草稿面板，锚点选了 `Label{... "这条消息的出处" ...}`。
但这行的**上一行**是一个 `View{` 容器的开头：

```
View{width: Fill height: Fit flow: Down spacing: 4      ← 原来是「出处」盒子的开头
    new_batch: true ...
    padding: ...
    Label{... "这条消息的出处" ...}                        ← 我把这一行替换掉了
```

结果：旧容器的 `View{` 三个属性行留成了**没有内容的孤儿**，新插的面板另起了一个 `View{`。
括号多开一层，`brace.py` 直接 FAIL。

**修法**：删掉孤儿开头即可。**教训**：插入新块时锚点要选**整个容器之前**，而不是容器内部的第一行。
已经写进 `AGENTS.md` 红线。

### 4. 顺带记一个排查手法

`brace.py` 只告诉你"文末还有一个 `{` 没闭合"，不告诉你**在哪**。
我写了个十几行的临时脚本：模拟同样的扫描逻辑，记录**每一行结束时的栈深**，
然后从最后一个 depth==0 的行往后打印所有 depth 变化 —— 失衡处立刻现形（这次是 3677 行）。
这个手法已经写进操作手册第 3 步（换行号即可复用）。
