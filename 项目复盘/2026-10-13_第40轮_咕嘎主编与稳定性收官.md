## 一、本轮改动清单（每一条都附实测）

### 1.1 MiniMax 官方钥匙全量接入

| 能力 | 实测 |
| --- | --- |
| 文本 | `POST https://api.minimax.chat/v1/chat/completions` → **200**。`MiniMax-M2 / M2.7 / M3` 都可用，**M3 最快（5.3 秒）** |
| 生图 | `POST https://api.minimaxi.com/v1/image_generation` → **200**，返回海螺 OSS 签名地址 |

**路上挖出两个真 bug**（都属于"界面不报错、只是永远没效果"那一类）：

1. **MiniMax 拒绝 `response_format: {"type":"json_object"}`**（400 `unknown response_format type 'json_object'`），
   而宿主 `model-service` 是**固定**发这个字段的 → 原生直连必然失败。
   修法：加一层本地转发服务 `tools/llm_shim.py`，负责摘字段、抬 `max_tokens`、剥 `<think>` 草稿。
2. **转发服务把 `/v1` 拼了两遍**（`.../v1` + `/v1/chat/completions`）→ 上游回 404。
   修法：`_dedup_v1()`。

**为什么这两个 bug 值钱**：它们和初赛被扣分的那条**是同一类**——代码写得好好的，一到真实环境就整条链子不通，
而界面上只会说一句"没接上模型"。

### 1.2 主编的嗓子 = 咕嘎的嗓子

**根因**：宿主起语音桥时默认执行 `python`（`model-service/src/voice/edge.rs` 的 `python_path()`），
而本机 PATH 里第一个 python 是**托管 3.13、没装 `edge_tts`**（系统 3.12 才有）。
桥一启动就 `No module named 'edge_tts'` → 咕嘎被迫退回 Windows 系统引擎 → **音色与桌面版桌宠完全不是一个人**。
用户反复反馈的"主编声音不是我桌宠那一款"，根子在这儿。

**修法（三层，缺一层都可能复发）**：

1. `tools/launch.py` 新增 `find_voice_python()`：探一个真装了 `edge_tts + miniaudio` 的解释器，
   写进宿主认的 **`GUGUA_VOICE_PYTHON`** 环境变量；
2. `tools/edge_tts_bridge.py` 新增 `reexec_if_needed()`：**被没装库的解释器拉起时，自己换过去**——
   不管谁拉起它都能活；
3. 桥的网络改成**先直连、失败再走代理**，并跳过 `127.0.0.1` 上的环境残留代理
   （原来只在"返回空音频"时退直连，而握手失败是**抛异常**，根本退不到）。

**顺带修掉两个真缺陷**（都是"开机后第一次做这件事就失败"）：
- `rv_start` / 智能体的 `read_brief` 直接拿 `vc_tts` 判，而语音能力是**用时再探**的 →
  开机后第一件事点「念给我听」永远得到"这台机器没有可用的语音合成"。→ 改为先探再念（`rv_wait`）。
- `rv_build` 用 `show_rows()`，而出报完成后卡片会回首页，那时它返回空 →
  在首页念报只能念出一句兜底。→ 新增 `rv_rows()` / `rv_intro()`，回退到磁盘上的 `last_brief.json`。

**实测**（宿主日志原文，8 段全部经 edge-tts）：

2. [edge-tts 软萌音] 第 1 条，Deep dive into Azure Maia 300 architecture。本鹅今天翻得最舒服的一页，就是它。
3. [edge-tts 软萌音] 第 2 条，Microsoft says Maia 300 racks will hold 96 chips and。转载的，本鹅看的是它背后那条原创够不够硬。

### 1.3 咕嘎 = 本报主编智能体（写进宪法）

- **编辑部宪法新增一条**（`charter` 的 `guga` 条，v1）——这条不是营销话术：
  读者问"你是什么"时 `read_charter` 会**原样念出来**，所以它必须和实现一致。原文：

  > 本报主编是咕嘎：一只当主编的企鹅，自称本鹅、管读者叫饲养员，声音是它自己那把软萌嗓子。
  > 它是本报唯一的智能体，挑选/导语/解读/核验/封面/追问这些活儿都是它调用宿主接入的大模型跑出来的；
  > 念报时它会在每条后面夹一句自己的私货，但私货一律标明是它说的，与事实分开陈述。

- **智能体自述改写**（`ag_system()`）：从"你是《晨报卡》的常驻 AI 主编"改成
  "你是咕嘎——一只当主编的企鹅……挑选新闻、写导语、逐条解读、决策台、核验台、画头版、写追问信，
  都是你调用宿主接入的大模型跑出来的；你说话用的也是你自己那把嗓子。"
  （仍在 `task` 的 4096 字节上限内：实测 1445 / 4096）
- **界面文案统一**（共 25 处）：`AI 主编` / `AI 编辑部` → 咕嘎。包括
  `咕嘎 · 主编 · 用时 11.9 秒 · 2742 tokens`、`接下来交给咕嘎（主编 · model.complete）挑选重点`、
  `咕嘎审阅了 16 条候选，选出 7 条。`
- **工作台面板写明身份**："本鹅是这份报纸的主编（智能体）：挑稿、写导语、解读、核验、画头版、开报，
  都是本鹅调用大模型干的。"

### 1.4 念报时夹带个人观点

**新增 `guga_takes` 池子**（24 条）+ 收尾池（5 条）+ 三个选取函数：

| 机制 | 说明 |
| --- | --- |
| 题材优先 | 命中 `芯片 / AI / 开源 / 安全 / 融资` 就说对应的那句（读者最容易有共鸣） |
| 档位兜底 | 没命中题材，就按信源档位说（一手 / 二手 / 传闻 / 转载）——"这条有多硬"本来也是最该告诉读者的 |
| 收尾 | 按**当期一手条数**分档 + 固定池子；`今天一手料 4 条，本鹅说话难得这么硬气。` |
| 确定性 | 种子 = `条号 × 13 + 标题长度`，**不用随机** —— 同一期念两遍听到的是同一句，复盘/录屏不会"怎么又不一样了" |
| 不花网络 | 本地池子，不额外问模型：念报是逐段同步念的，每条等一次模型往返会把节奏拖垮，模型一失败整段还会哑 |

**私货与事实的分界**：句号断开、另起一句，且一律以"本鹅"开头。这条规矩写进了宪法（见 1.3）。

**一个实测踩到的坑**：英文长标题动辄一百多字，而一段的上限是 150 字（`art_cut`）——
第 4 条念出来只剩标题，咕嘎的点评被整个挤掉了。→ 拼之前先把标题掐到 52 字（只影响"念出来的"，屏幕仍是完整标题）。

### 1.5 使用稳定性收官

| 问题 | 处理 |
| --- | --- |
| **启动期白屏** | 已修（`load_last()` 读旧 `cover.json` 缺 `sub` 抛错 → `boot()` 中止 → `cg_off()` 没注册 → 开屏 CG 永远盖着） |
| **运行期白屏** | 复现并定案：**引擎级渲染故障**（控件树完整、点击照常改状态，但窗口连自己画的标题栏都是白的，且反向滚/点击/改尺寸/最小化都救不回来）。触发偶发——400 次滚轮、200 次边缘拖拽、主编台开关、连拖桌宠都没能稳定复现。→ 新增 `tools/card_watchdog.py` 自动恢复 |
| **端口被残留占着** | 启动器 `pick_port()` 自愈：自己作品的残留就收掉，别人的就顺延 |
| **卡片被一起收走** | `octo --detach` 在 Windows 上从未真正分离（`start_new_session` 是 POSIX only）→ 改 `creationflags` |

**看门狗怎么判**（口径都写进注释了，避免以后误伤）：
连续 3 次（每 8 秒）同时满足「窗口整片纯白（色数 < 200、非白点 < 800）」+「`/snap` 里还有 ≥30 个控件」
才判定白屏 → `POST /quit` → 用同一个启动器拉起来。两道防误判：
`WindowFromPoint` 确认卡片没被别的窗口盖住（盖住就不算数）、pidfile 防重复上岗。

实测口径（本机 824×1504 窗口、采样约 1.1 万个点）：**正常页色数 2700~8600，白屏 27**——差三个数量级。
