# 第 30 轮：会说话的编辑部 —— 语音对话层 + 读者画像 + 本报记忆

日期：2026-09-29
作品：morning-brief（晨报卡）
本轮目标：让主编从「能打字使唤」变成「说得出、听得见」，并且这份报开始**认识读它的人**——
把每天的新闻积累成一份只属于这位读者的画像，和一份本报自己的往期档案（追一条线索）。

一句话总结：**别人做的是"AI 帮你读今天的新闻"，我们做的是一份会记住你、会追线索、还能开口说话的报纸。**

---

## 一、做了什么

### 1. 语音对话层（说得出、听得见）

**这一步真正的难点不在卡片里，在宿主里。** 上一轮交接文档写着「card-host 没有注册语音服务」——
我没有绕开它，而是把宿主补上了：

| 层 | 改动 | 位置 |
| --- | --- | --- |
| 宿主能力 | `llm` 服务新增 6 个方法：`speech`（本机语音能力）、`speak`、`speaking`、`listen_start`、`listen_poll`、`listen_stop` | `OctoSense-App-Hub/crates/llm-service/src/voice.rs`、`voice/stt.rs`、`voice/player.rs` |
| 宿主播放 | 安装 `cx.audio_output`，把服务渲染出的 PCM 送到扬声器 | `crates/card-host/src/host.rs` |
| 引擎 | 用 makepad 自带的 `makepad-system-speech`（Windows 走系统自带语音，不下模型、不联网） | 依赖声明 |

卡片侧只用官方 `host.request` 调用，一行设备代码都没有——**麦克风和扬声器都归宿主，卡片只拿到文字和声音**。
这正好符合平台的宿主服务契约（见 `docs/HOST-SERVICES.md`）。

实测（本机 Windows）：
- TTS：`Microsoft Huihui / Yaoyao / Kangkang` 三个中文声音，合成 345 字约 21 秒，子线程渲染不卡界面
- STT：`Windows.Media.SpeechRecognition`，中文识别可用（需要一次性打开系统的「在线语音识别」开关）
- 卡片上：点「说话」→ 按钮变「■ 正在听」，说完自动把话送进主编对话框；
  点「念这一期」→ 念导语 + 前三条标题；主编每次答完话，**自动配自己的声音说一遍**（可一键关掉）

**降级是设计的一部分**：这台机器没有语音能力时，语音按钮自动隐藏，文案改成「全程打字也算数」——
不让一个可选能力和产品捆绑。

### 2. 读者画像（这份报只为一个人编）

存在 `profile.json`（本地，不上传）：出报期数、读过多少条、各主题阅读计数、读者亲口说的长期偏好。

- 每读一条新闻，`pf_watch()` 按标题主题给画像加分
- 这些数据**倒灌进编辑部**：主编终审的提示词里多了一行「读者画像：这位读者最近常读：AI 12 次」
- 主编新增工具 `remember_reader`：读者说「记住：我偏好开源和芯片」，这句话进档案，以后每期都算数
- 首屏底部显示 `读者画像 · 已出报 2 期 · 读过 1 条 · 常读 AI`

这是把「新闻聚合」变成「个人刊物」的那一步。

### 3. 本报记忆（本地知识库 + 追一条线索）

存在 `archive.json`：每一期入选的条目都进档案（标题 / 来源 / 摘要片段 / 日期），上限 240 条。

- **检索完全本地**：`arc_find(q)` 按空格拆词、全部命中才返回（AND 语义），不联网、零费用
- **阅读页自动「追线索」**：打开一条新闻，如果本报过去报过同主题的条目，页面自动多出一块
  「本报追过这条线索 · 09-29 IPO prospectus: Anthropic reports...」
- 主编新增工具 `search_archive`：读者问「我们之前报过什么」，它去查本报档案并如实回答
- 首屏底部显示 `本报记忆 19 条`

**这条线的意义**：从「每天一份新报纸」变成「一份有连续性的报纸」。

### 4. 工具层从 12 个扩到 15 个

| 新工具 | 作用 |
| --- | --- |
| `search_archive` | 查本报往期报道（本地检索） |
| `remember_reader` | 记住读者亲口说的长期偏好 |
| `speak` | 把一句话念出来（读者明确要求时才用） |

系统提示里同时写清边界：**「search_archive 只查本报档案，不是联网搜索；问外面的事、你不知道的，如实说不知道，不要编。」**
——这是守住「可核验」这条产品底线。

### 5. UI 清爽化（页面干净、意图明显）

- 首屏加一行说明：「这份报会记住你读过的内容，越读越懂你；右下角『AI 主编』可以说话、可以查本报档案」
- 对话条的能力清单从 15 项长串压成一句话：「能改设置 · 能出报 · 能翻页 · 能查本报档案 · 能说话」
- 语音按钮和状态文字**分行**（原来挤在一行，文字被压成竖条）
- 底部记忆标签固定宽度，不再把「AI 主编」按钮挤到只剩 23px
- 对话区高度 168 → 230px（原来长回答会被截成半行）

## 二、本轮修掉的 bug

### 1. `ok` 是 splash 保留字，不能当变量名

写语音探测时用了 `let ok = tts["available"]`，整段逻辑静默失效——探测结果永远显示「语音不可用」。
`ok / me / scope / self / _` 都在保留字清单里（交接文档早写了），这次是**自己踩**。改成 `tv / sv` 后立刻正常。

### 2. `pf_t` 里只有 id，却去取 `t.label`

画像数据结构是 `[{id: "ai", n: 12}]`（只存 id 和计数），但我写了 `t.label` 取标签——
运行时抛 `property label not found in prototype chain`，**整个 card-host 进程退出**。
修法：加一个纯函数 `pf_label(id)` 去 `topics` 里按 id 查标签。

### 3. 阅读页会永远卡在「正在打开这条新闻的官方页面…」

境外站点（TechMeme）抓取偶尔极慢甚至挂住，`story_finish()` 永远等不到结果。
加 `story_watch(12)` 看门狗：12 秒还没落地就跳过官方原文，直接进 AI 解读，并在界面上说明这次原文没取到。

## 四、为什么把改动放在宿主（而不是绕开）

这是本轮最值得说清的一个决策。

上一轮结论是「card-host 根本没注册语音服务，不是卡片里写几行能接上的」。可选路有三条：
1. 放弃语音，改用文字模拟（不诚实，也拿不到分）
2. 在卡片里想办法偷用设备（平台明确封死：没有 `microphone` 之外的路径，且卡片不该碰设备）
3. **把宿主补齐**——按平台自己的规矩加服务

选了第 3 条，理由：
- 平台文档 `HOST-SERVICES.md` 就写着「需要什么就在 shell 里加服务，不要在 bundle 里绕」——这是**平台鼓励的正确做法**
- 具体实现直接用官方自带的语音能力（`makepad-system-speech`），不引外部依赖、不下模型
- 卡片侧零设备代码，能力仍走 `host.request` + manifest 的 `llm` 声明，权限模型没有被破坏

宿主改动已导出为 patch：`my-entry/patches/host-voice.patch`（见该目录 README）。
