# 第 34 轮复盘 · 出报链路可回放 + 提示词版本化

**日期**：2026-10-01
**主代码**：`my-entry/morning-brief/bundle/main.splash`，**4406 → 4728 行**
**本轮关键词**：可审计、可复盘、编辑部宪法

---

## 一句话概括

前几轮让这份报**能被审问**（断言 / 更正 / 口径 / 落选四条台账）；
这一轮让它**能被复盘** —— 把出报过程本身摊开，并且第一次把「它照着哪版规矩编的」写清楚。

---

## 一、为什么做这个：一个还没被填上的洞

到第 33 轮，这份报已经能回答很多尖锐的问题：

| 读者可以问 | 靠什么答 |
| --- | --- |
| 你报错过吗？更正过几次？ | `read_ledger` 查更正台账 |
| 这条消息你是什么时候听到的？ | 线索时间轴（爆料／跟进／已确认） |
| 今天有几个来源在打架？ | 口径不一致卡 |
| 你砍掉了什么？ | 落选公开 |

但它答不了这个：**「你今天是怎么选的？」**

这不是一个小问题。更正栏证明它敢认错，但**判断一次取舍是否合理，得看到作出取舍时的现场** ——
当时的候选池有多大、三位初审各自说了什么、主编的完整推理是什么。
只给结论让人评价，等于让人盲评。而 AI 新闻产品到现在，几乎全是黑盒：输入进去、文章出来，中间什么都不留。

新闻业有可审计的传统：编辑部会议记录、编辑方针手册、署名与更正制度。
这一轮就是**把这两样补上**。

## 二、做了什么

### 1. 出报链路留痕（`trail.json`）

对应编辑部的三层，留三层的痕迹：

- **候选池**：本期扫了多少条原始、多少条进了池子、**池子里的标题是什么**。
  以前只有一个淘汰率数字；现在可以核对「某条明明在池子里，为什么没被讨论」。
- **三位初审的原话**：技术 / 行业 / 读者三位编辑**各自独立写的那句点评**，一字不改留档。
  **谁有没有串供，看得见。**（`panel_put()` 里顺手取，`trail_set_panel()`）
- **主编终审**：导语原话 + 每一条的入选理由 + 被砍掉的三条及理由。
  这是整份报最有信息量的一屏 —— **取舍的理由，而不是取舍的结果**。（`trail_set_judge()`）

外加 `forecast`（押了什么）、`fact`（核对结果）、`cover`（头版标语）三项元数据。

**落盘规则**：只留最近三期。留痕是为了复盘，不是为了囤积。

> 一个坑：同一期会被写多次（终审后落一次，forecast / factcheck / cover 回来各补一次）。
> `trail_save()` 必须**按 `date` 合并** —— 同一天的旧记录丢掉，只留最新最全的那份。
> 否则一期会入账四次，三期容量瞬间被一天填满。

### 2. 编辑部宪法（提示词版本化）

9 处喂给模型的 system 指令，第一次被抽出来集中到一张表（文件开头的 `charter` 数组），
每条带**版本号 + 一句条款说明**：

| id | 版本 | 条款 |
| --- | --- | --- |
| `ask` | v1 | 开报前的一问：两个选项必须互斥，且都能直接当成本期关注点 |
| `panel` | v1 | 三视角初审：技术 / 行业 / 读者各判各的，不许串供 |
| `judge` | **v2** | 主编终审：传闻最多 1 条且须写明未证实；一手同权重优先；公开砍掉的三条 |
| `story` | v1 | 逐条解读：写给不懂技术的普通人，两段，不复述标题 |
| `forecast` | **v2** | 预测与断言台账：预测须一周内可检验；claims 只写标题里看见的，不推测 |
| `factcheck` | v1 | 跨源核对与更正：宁可空着也不硬凑；略有出入不算推翻 |
| `cover` | v1 | 头版视觉：英文标语 + 无文字画面描述 |
| `interview` | v1 | 追问信：只问一个可验证的问题，不奉承不指控 |

**改动纪律**：改文案就升版本号，**不原地改**。
出报时 `charter` 版本号随 `trail` 一起落盘 —— 于是任何一期都能倒推回「它当时照着哪版规矩编的」。
这也为真做 A/B 留好了口子：想试 `judge v3`，加一条 v3 而不是覆盖 v2，两版可以并行跑不同期。

实现上，每处 system 前面拼一句 `[编辑部宪法 judge/v2]`，用 `charter_v("judge")` 取版本号 ——
**版本号只有一处定义**，改版本号不用去 9 个地方同步。

### 3. 结果页新增「回放」卡

位置：新闻列表之后、「没上的三条」之前。内容按三层结构渲染：

```
回放 · 这一期是怎么做出来的
取数：62 条原始 → 16 条入池（淘汰率见工作量卡）
三位初审各自的原话（互不商量）：
· 技术视角：……
· 行业视角：……
· 读者视角：……

主编终审原话：
导语：……
1. 某厂商发布新一代推理芯片
　为什么上：一手来源，规格齐全，且与昨日预测对上
砍：某社交平台的供应链截图 —— 信源太薄，仅一条未经证实的爆料

编辑部宪法 ask/v1 · panel/v1 · judge/v2 ·……
```

**零额外 LLM 调用** —— 用的都是本来就要落盘的数据，只是顺手写下来。

### 4. 主编新增两个工具（20 → 22）

- `read_trail` —— 回放最近一期的全过程。系统提示词里写死了：**照着当时的记录说，不要事后美化**。
- `read_charter` —— 如实念出编辑方针。系统提示词里写死了：**不要自己另编一套**。

这两个工具的共同点：**查的都是已经落盘的事实，不是模型现编的话。**
另外 `ag_context()` 里补上了「出报留痕」与「编辑方针」两行，让主编随时知道这两样东西存在。

## 四、踩到/避开的坑

1. **一期被写多次 → 必须按日期合并。** 见上文 `trail_save()`。
   最初写成 `box.push(trail)`，跑一期会入账四次，三期容量被一天占满。
2. **`trail_set_judge` 的入参别想当然。** 一开始写了个 `last_rows_guess()`，那个函数不存在。
   终审成功分支里 `picked` 已经被 `picks_from_ai()` 填好了，直接用 `picked`。
3. **UI 卡插错 pane。** 第一次插到 `story_pane`（阅读页）里去了 ——
   因为「没上的三条」那句文案在文件里出现的位置，比我以为的靠后。
   **教训：插 UI 卡之前先 `grep -n` 确认目标行号落在哪个 `pane := View{}` 区间内。**
   而且要记住：`p.write_text()` 在脚本最后，前面任何一步 `assert` 失败，
   文件都不会被写 —— 别被「assert 过了」骗了，去 grep 确认文本真的进去了。
4. **转义层级。** Python 里写 `'\\n'` 到 splash 源码中应产生 `\n`（DSL 的换行）；
   写多行 `"""..."""` 匹配时，splash 源码里的字面量要写成 `\\n`。
   锚点匹配失败就用**行号定位 + 前后行内容断言**代替长字符串匹配，稳。
