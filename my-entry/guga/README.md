# 咕嘎桌宠 → 晨报卡 · 迁移说明

> 这一目录存放「咕嘎桌宠」迁移进晨报卡时用到的**离线加工脚本**与说明。
> 桌面版桌宠本体在 `~/.zcode/workspace/default/guga-penguin-pet`（Python + PyQt，不在本仓库里）。

## 一、迁了什么

咕嘎原来的形态是一个独立的 Windows 桌面宠物（PyQt 悬浮窗）：呼吸、眨眼、蹦跳、
受惊抖、偷偷探头、傲娇摆头、说话动嘴，加上一套「娇憨＋傲娇」的话术与状态系统
（饱食度/心情/精力），右键还有互动菜单。

迁进晨报卡后，它成了**卡片里的常驻主编形象**：住在底部工具条右侧（46×64），
出报阶段的表情照旧（出报=开心、休刊=难过、取数中=打盹），外加完整的桌宠行为：

| 桌宠能力 | 卡片里的实现 | 运行表现 |
| --- | --- | --- |
| 呼吸（1 秒一拍） | 基础帧 ↔ `*_breath` 帧交替 | 常驻可见，始终在动 |
| 眨眼 | 素材里没有独立眨眼帧，跳过（避免伪造） | — |
| 蹦跳 `bounce` | `cheer_squat → cheer_jump → cheer_squat` 序列 | 点一下/逗逗时 |
| 受惊抖 `shake` | `surprised_wobL/wobR` 交替 | 点击受惊时 |
| 傲娇摆头 `tsundere` | `pout_swingL/swingR` 慢摆 | 傲娇台词时 |
| 偷偷探头 `peek` | `idle_peek` | 闲聊/害羞台词时 |
| 指点江山 `point` | `pout_go`（前倾） | 讲报纸态度时 |
| 说话动嘴 | `talk0/1/2` 三帧循环（闭嘴/微张/大张） | **只在该机器真能出声时**（见下） |
| 闲时小动作 | 每 10–25 秒随机蹦/探头/摆头 | 空闲时让它「活着」 |
| 点击互动 | 点一下 = 戳它；双击（触屏长按）= 互动菜单 | 见「四、怎么看效果」 |
| 话术人格 | 40 条台词，自称「本鹅」、叫用户「饲养员」 | 气泡弹出 2–9 秒 |
| 状态系统 | 饱食度/心情/精力，20 秒一滴，存 `guga_pet.json` | 饿了点它会说饿 |
| 语音对话 | 接应用既有的主编语音层（`llm.speak`） | 有语音则念 + 动嘴 |

**炉石相关的部分全部剔除**：桌宠里的战棋军师人格、棋盘分析、拔线、胜率解读、
阵容展望、RAG 知识库（`knowledge/battlegrounds/*`）、卡牌数据（`data/cards_zhcn.json`）
一律未迁移；台词里凡是提酒馆/战棋的都改写成了本报与编辑部题材。整个 `main.splash`
里现在没有任何「炉石/酒馆/战棋/拔线/军师」字样。

## 二、为什么长这样（技术约束）

卡片的 splash 脚本**没有位移/缩放/旋转这类变换原语**，桌宠里那些实时算出来的
动作没法直接搬。所以采取「离线烘焙」：

```
桌宠的立绘（216×300 透明 PNG）
  → bake_motion_frames.py  把桌宠的变换参数预先算成静止帧（16 张，存 bundle/assets/guga/motion/）
  → make_talk_frames.py    用「嘴部补丁法」做出三张口型帧（talk0/1/2）
运行时 main.splash 只管换帧（pet_apply / pet_run_seq / pet_talk_*）
```

换帧等于同一套动作语义，且运行开销只有一次 `set_src`。

### 嘴部补丁法是怎么定位的

两张原画（闭嘴基准帧、张嘴帧）人物位置不同：用模板匹配测得张嘴帧相对基准帧偏
`(-10, +13)`。嘴部矩形 `(137,162)-(206,226)` 是用 10px 网格人工核对的；打了 14px
羽化避免接缝。中张嘴（talk1）不做第二张原画对齐，直接用同一张嘴按 55% 不透明度
合成——天然对齐。

### 为什么说话不动嘴时也不假装

`llm` 语音服务**只服务系统应用**（官方规定），本应用按惯例不申请 `llm` 能力，
所以在这台机器上咕嘎只会「出气泡 + 换表情」，不会动嘴。宿主若换到带语音的构建，
`vc_tts` 为真时口型自动接上——不用改代码。

另外应用**刻意不在互动路径上探测语音**：没被授予 `llm` 时这次探测必被拒，而被拒
路径在运行时会同步重入 isolate，打出 `pop_stack_resolved on empty stack`
（详见 `生态贡献/ISSUE-03`）。启动时不探、互动时也不探，是两轮迭代后定下的口径。

## 三、重新生成素材

```bash
# 1) 动作帧（需要桌宠素材在 bundle/assets/guga/ 下）
python my-entry/guga/bake_motion_frames.py

# 2) 口型帧（需要原画在 C:\Users\...\Desktop\图片库\咕嘎说话动作）
python my-entry/guga/make_talk_frames.py
```

两个脚本都会打印每张图的留白（有没有被画布裁掉）与文件大小。重新烘焙后
**务必**再把基础帧与 motion 帧统一缩到同一尺寸（当前 160×222），否则换帧会跳。

## 四、怎么看效果（不用点鼠标）

```bash
# 起一个实例（端口别和并行开发用的撞：8160/8211 是别人在用的）
python tools/launch.py --port 8188

# 点一下企鹅（坐标是逻辑像素；底部工具条的企鹅在 x≈252, y≈700）
curl -s "127.0.0.1:8188/click?x=252&y=700"

# 双击打开互动菜单（两次点击间隔必须 < 0.3 秒，运行时的判定阈值）
(curl -s "127.0.0.1:8188/click?x=252&y=700"; curl -s "127.0.0.1:8188/click?x=252&y=700")

# 截图
curl -s "127.0.0.1:8188/g?raw=1" -o shot.png
```

实机证据在 `my-entry/evidence/r37_guga_*.png`（点击回话、菜单、摸互动、呼吸时间轴）。

## 五、踩过的坑

1. **`pointer_events: Ignore` 不存在**：气泡浮层最初用全屏 Overlay + `pointer_events`
   让点击穿透，但运行时不认识这个属性（没有 `PointerEvents`，`Hit` 系统也没有
   穿透开关）。改成「浮层只占右上角该占的部分」——现在气泡/菜单是底部右对齐的
   定宽组，不铺满全屏，不需要穿透。
2. **外层容器写死 `visible: false` 会把内层一起藏掉**：气泡最初两层容器都写
   `visible: false`，内层再切可见也没用。改成外层常开、气泡/菜单自身控制可见性。
3. **长按（long press）在 Windows 鼠标上不触发**：运行时只在触屏上产生
   `Event::LongPress`（`finger.rs` 的 `Hit::FingerLongPress` 只在 touch 设备路径
   上生成）。菜单的鼠标入口改成了**双击**（`gesture_view.rs` 的 `DOUBLE_TAP_SECONDS
   = 0.3`，两次 click 间隔要小于这个值），触屏上长按依然可用。
4. **连点企鹅会同时跑几条动作序列**：`start_timeout` 的旧定时器不会因为新动作而
   取消，帧速翻倍。加了序列代次（`pet_seq_gen`），旧定时器看到代次不符就自觉退出。
5. **动作序列不同步气泡**：`pet_run_seq` 只换帧，气泡要等下一次心跳（最多 1 秒）
   才出现。`pet_say_line` 里补了一次 `pet_sync_bubble()`，现在点击立刻出气泡。
6. **双击间隔实测**：`curl` 两次 `click` 之间如果夹了截图（~0.5s）就超过 0.3 秒
   判定窗口，菜单打不开。测试脚本要把两次点击放同一个 `( ; )` 里。
7. **并行编辑**：本迁移与另一条开发线（r36/r37：取数、生图、语音评测）同时改
   `main.splash`。补丁全部做在咕嘎自己的函数区/底部工具条/浮层三处，并保持
   `tools/brace.py`、`tools/audit_widgets.py`、`tools/audit_globals.py` 三道体检全绿。
   动手前先 `git diff --stat` 看一眼别人的改动范围。
